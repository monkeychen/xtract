## 1. 产品定位

Xtract 是一款面向专业技术人员、新媒体创作者与投研分析师的**高信噪比 X (Twitter) 实时情报雷达与 AI 结构化研报系统**。

采用纯 Node.js / Electron (TypeScript) 单运行时架构，同一二进制支持双模驱动：

- **GUI 桌面工作台**：无参启动即唤出唯一核心视窗「XTRACT 情报工作台」，提供四维情报聚合、长文沉浸式阅读、免落盘视频流式播放与全局设置中心；
- **Headless CLI**：带参启动命中命令行白名单时直接进入 CLI 模式，stdout 输出标准 JSON，stderr 输出诊断进度，支持终端与下游 Agent 管道组合。

## 3. 不可动摇的设计红线

1. **纯单运行时**：严禁引入外挂 Python 进程、第三方逆向爬虫库，或拉起「双重 Chromium」。必须通过单一 Node.js / Electron 运行时与 Playwright 官方网络流嗅探保障低内存与零维护成本。
2. **用户体验最高准则**：绝不允许白屏卡死、无上限死等、静默吞没错误。404 与风控必须 3 秒内显式提示并给出下一步动作。
3. **约束先行与真实探针**：严禁脱离实际凭空编造 DOM / GraphQL 结构；涉及复杂网络嗅探时探针先行。严禁硬编码不存在的假用户或假数据。
4. **确定性工程与非确定性智能分离**：抓取、反爬、去重、时效校验、互动过滤属于确定性工程，严禁依赖大模型；观点聚类、辩证推演、因果分析与选题交给大模型。

## 4. 核心功能规格 (Feature Specs)

### 4.1 运行时与双模调度架构

- **CLI 参数白名单派发**：有参启动命中白名单时进入 Headless CLI，stdout 输出纯 JSON，stderr 输出诊断进度；无参启动进入图形界面；
- **单一 Chromium**：全程复用一个 Playwright 会话，禁止因多源抓取而并发拉起多个浏览器。

### 4.2 情报采集

#### 4.2.1 四维情报源
1. `Following`（关注时间线）：默认仅拉取长文与专栏；
2. `Search`（全网搜索）：输入框默认绝对为空，空时展示本地全量库；输入关键词执行本地全库模糊检索；支持推文 URL 穿透直接同步；
3. `User`（博主追踪）：输入用户名定向拉取，并跨库检索该博主的全部本地推文；
4. `List`（X 列表）：通过 `list_id` 建立**物理分区隔离**，列表内容绝不串染。

> **实现约束**：`Search` 源的查询 `sourceType` 为 `all`（检索本地全库），**不是** `search`。这是最易被"顺手改成更一致"而改坏的高危语义。

#### 4.2.2 官方网络流透明拦截
驱动真实 Chrome 加载目标页面，监听由 X 官方前端合法发出的 GraphQL 响应（`HomeLatestTimeline`、`SearchTimeline` 等）。零逆向成本，完全免疫前端改版。

#### 4.2.3 互动信噪比门槛过滤
支持点赞/转推门槛（`--min-likes`、`--min-retweets`），在采集、检索、导出、早报**全链路**生效。工作台顶部常驻 `全部` / `50+ 赞` / `200+ 赞` 药丸，点击时毫秒级过滤本地列表，**不发起多余网络请求**。

#### 4.2.4 严格数量约束与提前终止
用户选择抓取条数（20 / 50 / 100 篇）后，抓取流水线在滚动嗅探到目标篇数时**立即 break 退出**，严禁无上限死滚。分页数按 `Math.max(1, Math.ceil(limit / 20))` 计算。

#### 4.2.5 长推文与专栏默认过滤
`FETCH_ONLY_LONG_TWEETS` 默认开启，自动过滤单句闲聊短推文，仅抓取长推文 (Note Tweet) 与专栏文章 (X Article)。专栏/长推文的判定逻辑在系统中**只允许存在一份实现**。

#### 4.2.6 推广广告自动剥离
数据入库前自动剥离所有 `promoted-tweet` 信息流广告，保证知识库与研报纯净。

#### 4.2.7 精准单推同步
搜索词或 URL 中匹配 `status/(\d{5,})` 或纯数字 ID 时，走单篇精准同步通道（含 Markdown 导出），而非全量搜索。ID 少于 5 位不匹配，避免把普通数字误判为推文 ID。

### 4.3 存储与归档

- **用户可配置的数据保存根目录**：统一由设置项指定数据保存根目录（环境变量 `XTRACT_STORAGE_ROOT`），默认路径为 `~/Documents/Xtract`。**不区分开发态与生产态，统一由设置指定，子目录名固定**；
- **自包含数据物理架构**：
  - **持久化配置 (`config.env`)**：存放于 `<storageRoot>/config.env`，双轨级联加载，保证打包后 GUI 配置修改持久有效且随目录便携迁移；
  - **数据与缓存 (`data/`)**：统一存放于 `<storageRoot>/data/`，包含 SQLite 数据库 `tweets.db`、认证会话 `auth_state.json`、浏览器环境 `browser_profile/` 与原始网络备份 `data/raw/`；
  - **文章产物归档 (`articles/`)**：统一存放于 `<storageRoot>/articles/`，包含单推自包含 Page Bundle `articles/{作者}/{推文ID}/index.md`；
  - **研报与早报中心 (`reports/`)**：统一存放于 `<storageRoot>/reports/`，包含每日早报与全网趋势深度研报（`YYYY-MM-DD.md` / `trends_YYYY-MM-DD.md`）；
- **better-sqlite3 增量去重**：以 `tweet_id` 为唯一主键，只记录增量，定时多次抓取不重复消耗 Token；
- **来源不可变**：`source_type` 以**首次抓取入库时的来源为准**，后续在其他源再次抓到同一推文时判为主键重复直接忽略，绝不覆盖；
- **ISO-8601 物理时间倒序**：RFC2822 原生日期全量标准化为 ISO-8601，确保 `created_at DESC` 在索引与展示层 100% 物理单调倒序；
- **自包含 Page Bundle**：导出为 `<storageRoot>/articles/{作者}/{推文ID}/index.md` + 同级 `images/`，相对链接不依赖外部服务；**作者名缺失时必须回退为 `tweet`**，严禁产出 `undefined/...`；
- **两阶段强一致级联清理**：删除推文时同时物理删除 SQLite 记录与 `<storageRoot>/articles/{作者}/{推文ID}/` 目录（含配图），保持强一致；提供 `--dry-run` 预览与二次确认弹窗防误删，空作者目录自动修剪。

### 4.4 桌面情报工作台

#### 4.4.1 唯一核心视窗
界面**只有一个**核心视窗「XTRACT 情报工作台」，四维数据源以顶部胶囊极速切换，右侧详情区自包含研读卡片。不存在二级 Tab。

#### 4.4.2 全选勾选态的集合语义
全选复选框的选中态 MUST 基于「每一项可见推文是否都在勾选集合中」判定。**严禁**用集合大小相等判定——关键词过滤缩小可见范围后，勾选集合中残留的已过滤 ID 会导致误判为「未全选」。

#### 4.4.3 切源时的浮层清理
切换数据源时 MUST 一并关闭删除确认弹窗、批量删除确认弹窗与图片灯箱。这些浮层的确认动作若跨越数据源存活，会作用于新数据源下的推文。

#### 4.4.4 条件保全式增量加载
「加载更早」按钮 MUST 携带当前数据源与全部筛选条件（`source_type`、`minLikes`、关键词或博主名）作为 offset 增量加载；已无更多时明确呈现「已加载全部 N 篇」并禁用；无数据时展示友好空态，**禁止出现无任何加载却谎称完成的假状态**。

#### 4.4.5 浮层与键盘可达
下拉菜单、图片灯箱、批量栏均支持 ESC 键关闭；点击配图触发灯箱，复制直链与系统浏览器打开双轨可达。

#### 4.4.6 批量导出必须真实落盘
点击「导出 Markdown」时，MUST 对每篇选中推文真实调用单推导出链路生成 Page Bundle。**严禁仅弹出成功提示而不产生任何文件。** 导出完成后定位到首个产物所在目录；部分推文失败时如实报告成功与失败数量，失败项保持勾选态以便重试。

#### 4.4.7 浏览器降级演示模式的显式标识
页面在裸浏览器中打开（未注入 `window.xtractAPI`）时，MUST 在顶部显示醒目提示条，说明当前为示例数据且无法抓取 X 或调用大模型，并指引改用 `pnpm dev` 启动桌面端。会话状态呈现为「未连接」，**严禁伪造账号身份**；设置抽屉凭据输入框保持为空，**严禁内置任何形似真实密钥的占位串**。

### 4.5 阅读与媒体呈现

#### 4.5.1 原生 TweetMarkdown 引擎
定制轻量解析器渲染 H1-H4 标题、中文章节序号、列表项与代码块。**彻底废弃**粗糙的纯文本 `pre-wrap` 展示。自动识别 X Article 专栏的 `> **核心摘要 / 提要**:` 引用块，渲染为高光速览卡片 (⚡)。行距与段落自适应。

> **实现约束**：正文中出现字面量 `\n\n` 时必须反转义还原为真实段落，严禁把转义串直接展示给用户。

#### 4.5.2 视频免落盘按需流式播放
- 严格 `preload="none"`，未点击播放前只显示封面与播放按钮，消耗 **0KB 静默流量**；
- 主进程挂载会话代理并伪装 `Referer: https://x.com/` 突破防盗链；
- 提供【📋 复制直链】与【🌐 在系统浏览器播放 ↗】双轨直达，并具备错误兜底 Overlay。

> **实现约束**：非视频推文的 `posterUrl` MUST 为 `undefined`，严禁因封面提取逻辑把首张真实配图排挤掉。

#### 4.5.3 图文网格与高斯模糊灯箱
解耦视频 poster 过滤；单图高清呈现，双图/四图自动对齐网格。点击配图呼出全屏高斯模糊遮罩预览，支持 ESC 退出与浏览器原图直达。

#### 4.5.4 富文本超链接自愈
自动识别 `t.co` 短链还原为可点击链接，安全剔除正文末尾多余媒体短链，点击以系统浏览器唤起。

#### 4.5.5 转推与引用推文卡片
详情区完整呈现转推内容与被引用推文，保持原始语境。

### 4.6 大模型调度与研报

#### 4.6.1 7 大厂商统一驱动
`BaseLLMProvider` 抽象统一封装 Gemini、OpenAI、DeepSeek、通义千问、智谱、MiniMax、Kimi。全量默认开启 high 级长思维链推理。

#### 4.6.2 双轨认证
- **API-Key 模式**：标准密钥接入；
- **账号订阅免 Key 模式**：如 Gemini 走账号通道；
- **专属套餐端点自动识别**：阿里 Token Plan（`sk-sp-`）与智谱 Coding Plan 智能路由到高吞吐端点。

#### 4.6.3 深度推理可视化控制
设置抽屉提供推理开关与 3 级强度（轻量 / 标准 / 深度），实时持久化生效。

#### 4.6.4 趋势研报流水线
全网热搜嗅探 → AI 搜索词提炼 → 安全串行下钻（2s 拟人节流）→ SSE 流式深度研报生成。生成过程以流式反馈消除长推理的黑屏焦虑。

### 4.7 设置、安全与质量门禁

#### 4.7.1 原生免 Cookie 登录捕获
设置抽屉调起原生隔离会话窗口供用户登录 X，成功后秒级自动截获 `auth_token` 与 `ct0` 并持久化。**用户无需用开发者工具（F12）手动查 Token。**

#### 4.7.2 抓取过滤规则可视化控制
设置抽屉卡片式开关：抓取长推文/专栏规则、抓取作者追评规则。

#### 4.7.3 单推作者追评受控（Default-Off）
单篇推文抓取时**默认仅获取主推文本体**，自动过滤作者追评。GUI 提供卡片开关，CLI 提供 `--author-replies` / `--no-author-replies`，且具备**缓存自愈**能力（显式传参但本地无追评时自动补全）。导出 Markdown 时消除多余的 `### 篇章` 碎片。

#### 4.7.4 本地数据存储根目录配置与二级子目录固定
设置抽屉提供「数据存储根目录」配置项（环境变量 `XTRACT_STORAGE_ROOT`），默认值为 `~/Documents/Xtract`：
- **不区分开发态与生产态**：统一以此根目录为基准，开发与生产数据完全互通且永不随更新丢失；
- **二级目录固定**：数据与缓存固定于 `<storageRoot>/data/`，导出的文章与研报固定于 `<storageRoot>/articles/`，用户不可篡改子目录名以确保程序契约强一致；
- **配置持久化与热生效**：设置中修改后即时热切换数据库与文章输出管道，自动递归创建缺失目录。

#### 4.7.5 质量门禁
交付前必须全量跑通四道门禁，统一入口为单条命令：

```bash
pnpm verify   # 依次执行 lint → test → tsc --noEmit → vite build
```

任一环节失败即中断并返回非零退出码。

## 5. 重大设计决策与功能剥离记录

> 以下功能经实际业务验证后被主动砍掉。**严禁后续开发者或 AI 重新引入。**

### 5.1 GUI 二级 Tab（「趋势雷达」与「智能研报」）
- **取消原因**：早期从「功能完备性」出发设计了二级 Tab，但用户核心心智是「沉浸式阅读与精选内参」，多 Tab 往返造成严重体验割裂与认知负担。
- **对用户的影响**：收敛为唯一工作台视窗，操作路径大幅缩短；趋势研报能力移交至 CLI 自动化管道，各得其所。

### 5.2 视频 `preload="metadata"` 静默探测
- **取消原因**：切推文时静默向视频 CDN 发起 Range 探测，遭遇代理延迟触发缓冲转圈，无故消耗代理流量并造成卡顿。
- **对用户的影响**：改为 `preload="none"`，未点击播放前零流量、零转圈。

### 5.3 单推抓取默认捕获作者追评
- **取消原因**：多数长推文只需看首发主帖，默认全量拉取追评导致列表充斥同作者连续短推文、等待耗时成倍增加、导出 Markdown 产生冗余篇章。
- **对用户的影响**：默认关闭，按需显式开启。

### 5.4 纯文本 `pre-wrap` 详情展示
- **取消原因**：排版粗糙、链接无法点击、专栏文章可读性极差。
- **对用户的影响**：由 TweetMarkdown 引擎全面取代。

### 5.5 硬编码假用户与假数据
- **取消原因**：伪造的账号身份、凭据占位串与示例推文会使用户误以为功能正常，且形似真实密钥的字符串存在安全风险。
- **对用户的影响**：降级模式显式提示，桌面端代码路径不再读取任何示例数据。
