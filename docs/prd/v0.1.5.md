# Xtract PRD - v0.1.5（批量导出至指定目录与打包自动清理）

> **版本标识**：v0.1.5  
> **状态**：✅ 已评审通过（Approved）  
> **前置版本**：[v0.1.4 发版说明](../archive/v0.1.4/release-v0.1.4.md)  
> **版本性质**：核心工作流提效——将工作台「批量导出 Markdown」从原地重复覆盖升级为**可指定目标目录、支持合并为单一自包含目录或按篇独立目录、缺全文自动静默补齐、媒体复用缓存且视频下载联动设置开关**的完整导出链路；同时实现本地打包前自动清理历史产物。

---

## 1. 背景与目标

1. **现有「批量导出 Markdown」形同虚设且违背用户心智**：
   - 桌面工作台点击单篇推文时，后台已无条件在默认目录 `~/Documents/Xtract/articles/{作者}/{推文ID}/` 生成了自包含 Page Bundle；
   - 此前多选后点击浮动条「导出 Markdown」，只是对勾选推文再调用一遍单篇查看接口原地覆盖同名文件，既不能选择目标目录（如 Obsidian 知识库、桌面项目文件夹或 NotebookLM 素材目录），也无法将多篇不同作者的文章汇总到一个目录集中带走，更缺少导出进度反馈。
2. **本地打包历史产物持续堆积**：
   - `release/` 目录不会自动清理旧版 `.dmg` / `.exe` / `.blockmap` / 解压目录，累计数个版本后轻松占用超过 1 GB 磁盘空间。

**本版目标**：让用户多选文章后可一键导出到任意指定位置，自由选择「合并为单一目录（1 份合并 `index.md` + 统一素材子目录）」或「按篇独立目录」，导出前自动静默补齐未展开全文，视频下载遵循设置中的既有开关；并让每次本地打包自动清理历史 `release/` 产物。

---

## 2. 用户故事

- **US1（指定位置与单目录合并导出）**：作为知识管理者与内容创作者，我希望在左侧列表多选几篇文章后，能够指定导出的目标文件夹，并选择将它们合并成一个单一自包含目录（含 1 份带目录索引的合并 Markdown 与统一的 `images/`/`videos/` 素材子目录）或按篇扁平导出为独立目录，从而方便地直接导入 Obsidian、NotebookLM 或交付写作素材。
- **US2（静默补齐全文与零冗余配置）**：作为日常使用者，我希望批量导出时，对那些刚抓取还没点开看过的未展开 X Article / 长推文，系统自动在后台静默补齐完整正文，且图片/视频优先复用本地缓存、视频是否下载直接遵循「设置」里的既有开关，无需每次重复勾选一堆选项。
- **US3（干净的本地打包环境）**：作为维护者，我希望每次执行 `pnpm pack:mac` / `pack:win` / `pack:all` / `pack:dir` 前系统自动清理上次遗留的 `release/` 历史包体，避免磁盘被旧版本安装包默默占满。

## 3. 功能需求与验收标准 (F & AC)

> 功能编号全局连续，接续 `v0.1.3`（F1–F5）。

### F6：多选文章批量导出 Markdown（指定目录 + 合并/独立双模式 + 静默补齐）
在工作台底部浮动批量操作条点击「导出 Markdown」时，呼出配置弹窗并执行完整的批量导出闭环。

- **AC6.1（导出配置弹窗与模式切换）**：
  - 点击浮动条「导出 Markdown」按钮（`#btn-batch-export`）打开配置弹窗（`#batch-export-dialog`），标题显示已选篇数；
  - 提供两种互斥导出结构单选并记忆上次选择（`localStorage('xtract:studio:exportMode')`，默认 `merged`）：
    - **合并为单一目录（`merged`）**：在目标目录下创建时间戳目录 `xtract_export_YYYY-MM-DD_HHMMSS/`，内含 1 份带目录索引（TOC）的合并 `index.md` 及统一素材子目录 `images/`（及按需 `videos/`）；
    - **按篇独立目录（`separate`）**：在目标目录下扁平生成 `{作者}_{推文ID}/index.md` 及各自 `images/`（及按需 `videos/`）。
- **AC6.2（自定义目标目录选择与自动引导）**：
  - 弹窗展示当前选定的导出目录路径，记忆上次导出目录（`localStorage('xtract:studio:lastExportDir')`），点击「选择目录…」调用系统原生目录选择器（`selectDirectory`）；
  - 若尚未选择目录直接点击「开始导出」，系统自动先弹出目录选择框，选定后直接开始导出；取消选择则保持弹窗不报错。
- **AC6.3（缺全文自动静默补齐与单篇容错）**：
  - 导出前逐篇检查本地数据库记录；对本地缺失或 `isTweetContentIncomplete` 判定为未展开（如截断长推、仅标题预览的 X Article）的文章，自动调用 `fetchTweetAndStore` 静默同步完整全文并回写 SQLite；
  - 单篇联网补齐失败时，若本地已有旧内容则降级保留继续导出；若本地完全不存在则记入 `failed` 列表，不中断其余文章导出。
- **AC6.4（素材本地化、缓存复用与视频开关联动）**：
  - 合并目录下所有图片文件名带 `{tweet_id}_` 前缀防止跨篇重名冲突，Markdown 正文图片链接自动改写为 `images/...` 相对路径；
  - 图片与视频优先从默认归档目录（`~/Documents/Xtract/articles/{作者}/{推文ID}/`）拷贝既有缓存，未命中缓存时再发起网络下载；
  - 视频是否下载/拷贝严格遵循设置中的 `AUTO_DOWNLOAD_VIDEOS` 开关（弹窗内以状态行实时展示当前策略）；开关关闭时不下载也不创建空 `videos/` 目录。
- **AC6.5（实时进度反馈与完成定位）**：
  - 导出过程中通过 `STREAM_EVENT`（`stage: 'batch_export'`）实时更新弹窗内进度条与当前处理篇目文案，且不影响左侧爬虫进度卡片；
  - 导出完成后自动关闭弹窗、在系统文件管理器高亮定位产物目录（`merged` 定位新建的合并目录，`separate` 定位目标目录）、弹出含篇数与媒体统计的 Toast；全部成功时自动清空列表勾选并刷新列表。
- **AC6.6（IPC 契约与自动化验证）**：
  - 新增 `IPC_CHANNELS.TWEETS_BATCH_EXPORT`（`'tweets:batch-export'`）与 `window.xtractAPI.batchExportTweets`；
  - 覆盖存储层合并导出单测、流水线静默补齐与双模式单测、IPC 契约单测，以及真实浏览器 GUI E2E Flow 25。

### F7：本地打包前自动清理历史产物
防止 `release/` 目录残留旧版本构建产物持续占用磁盘空间。

- **AC7.1（跨平台清理脚本）**：新增 `scripts/clean-release.ts` 与 `pnpm pack:clean`，删除 `release/` 全部历史产物并打印释放空间（MB），兼容 macOS 与 Windows，目录不存在时幂等退出码 0。
- **AC7.2（全量打包命令前置绑定）**：`pack:mac`、`pack:win`、`pack:all`、`pack:dir` 均前置执行 `pnpm pack:clean`，确保每次本地打包与 `pnpm verify` 均从干净 `release/` 开始，且与 GitHub Actions 双平台发版流水线完全兼容。

## 5. 非目标 (Out of Scope)

为防止范围蔓延，以下能力明确不纳入 `v0.1.5`：
- **不做 PDF / EPUB / DOCX 等多格式转换**：专注 Markdown + 本地素材目录的自包含通用格式；
- **不做自定义 Markdown 模板编辑器或自定义合并文件名输入框**：统一采用带时间戳与 TOC 目录的规范输出，减少交互负担；
- **不在导出弹窗内重复提供独立的「是否下载视频」复选框**：严格复用「设置」中已有的 `AUTO_DOWNLOAD_VIDEOS` 开关，保持单一配置事实源；
- **不新增 CLI 批量合并导出命令**：CLI 侧保持既有 `--export` 与 `--export-ids` 契约不变。
