## 1. 目标与设计决策

### 1.1 核心诉求
将 Xtract 从单纯的终端 CLI 升级为具有报刊质感（Warm Editorial）的桌面专属情报工作台，让专业研究员与内容创作者在一套丝滑的窗口中完成推特内参浏览、筛选与深度归档。

### 1.2 重大业务决策（功能剥离与收敛）
- ❌ **果断剥离不可用二级 Tab（「趋势雷达」与「智能研报」）**：
  早期设计的二级 Tab 导致用户在情报监控与研报提炼间操作割裂。系统全面回归第一性原理：**只保留唯一核心视窗——「XTRACT 情报工作台 (StudioView)」**，所有数据源集中统一呈现，大幅降低认知负荷。

---

## 2. 核心功能规格 (Feature Specs)

### 2.1 四维情报源极速切换
- **数据源分类**：
  1. `Following`（关注时间线）：默认仅拉取长文与专栏；
  2. `Search`（全网搜索）：输入框默认绝对为空，空时展示本地全量库，输入关键字全库搜索；支持推文 URL 穿透直接同步；
  3. `User`（博主追踪）：输入用户名定向拉取与跨库检索；
  4. `List`（X 列表）：基于推特公开或私人列表监听垂直领域动态。
- **X Lists 物理分区隔离**：通过 `list_id` 建立物理分区，列表内容绝不串染。

### 2.2 信噪比 (SNR) 动态门槛过滤
- **业务规则**：在工作台顶部常驻药丸过滤组件（`全部` / `50+ 赞` / `200+ 赞`）；
- **交互性能要求**：点击药丸时毫秒级过滤本地当前数据源列表，绝不发起多余网络请求。

### 2.3 全流抓取严格数量约束与提前终止 (Strict Early Stop)
- **业务规则**：用户在界面选择抓取条数（20 / 50 / 100 篇）；
- **核心约束**：抓取流水线在滚动嗅探到目标篇数时，**必须立即 break 退出**，严禁无上限死滚死等。

### 2.4 长推文与专栏默认抓取过滤
- **业务规则**：`FETCH_ONLY_LONG_TWEETS` 默认开启（`true`），自动过滤单句闲聊短推文，仅抓取长推文 (Note Tweet) 和专栏文章 (X Article)；
- **排版换行自愈**：统一反转义字面量 `\n\n` 字符，还原真实段落排版。

### 2.5 数据级联强一致物理清理
- **清理契约**：删除推文时，同时删除本地文件系统 `output/{author}/{tweet_id}/` 及其配图，并执行 SQLite 物理删除，保持文件与数据库 100% 强一致；
- **防误删保护**：必须指定筛选条件，支持 `--dry-run` 预览与二次确认弹窗。

### 2.6 全局设置抽屉 (Settings Drawer)
- **刊头状态指示**：展示推特会话有效性与代理状态；
- **原生登录捕获**：应用内调起原生登录窗口，自动提取并持久化 Cookie；
- **大模型长思维链配置**：支持深度推理开关与 3 级强度（Low / Medium / High）；
- **专属套餐自动路由**：阿里 Token Plan 与智谱 Coding Plan 专属端点智能识别。
