# Xtract PRD - v0.1.3（视频本地下载与拉取内容类型可配置）

> **版本标识**：v0.1.3  
> **状态**：✅ 已评审通过（Approved）  
> **前置版本**：[v0.1.2.md](v0.1.2.md)  
> **版本性质**：核心能力增强——打通短推、长推与 X Article 专栏（含内嵌视频推文）的视频本地下载与离线播放闭环；同时将批量拉取的内容类型升级为细粒度多选配置，默认聚焦高价值 X Article 专栏文章。

---

## 1. 背景与目标

1. **视频只能在线播、无法本地归档**：`v0.1.2` 仅支持视频免落盘在线流式播放，存在两个核心痛点：
   - 遇到高价值视频素材无法一键保存到本地 Page Bundle，离线或原帖删除后资产直接丢失；
   - 经真实探针验证（样本 `https://x.com/AdrianPunk115/status/2124098048842473619`），X Article 专栏正文内嵌的 `TWEET` 卡片中常携带多条高清（1080p / 4K）视频，现有解析器只保留了文字与链接，嵌入推文里的视频完全不可见也无法下载；且单条推文含多个视频时仅渲染首个视频。
2. **拉取内容过滤粒度不足**：现有设置仅提供「仅抓取长推文与专栏文章」二元开关，无法做到**只拉取 X Article 专栏文章**，导致日常拉取仍混入大量长推文或短推文噪音。

**本版目标**：让用户能把任意形态推文（短推、长推、X Article 及其内嵌推文）中的视频按需流式下载到 Page Bundle 并本地离线秒播；同时支持在设置中自由勾选要拉取的内容类型，默认仅拉取 X Article 专栏文章。

---

## 2. 用户故事

- **US1（视频本地沉淀）**：作为内容创作者，我希望在阅读短推、长推或 X Article（包括文章中嵌入的视频推文）时，能够一键将高清视频下载到该推文的本地归档目录并支持进度显示、取消、访达定位与离线播放，这样我可以把视频素材连同图文一起长期归档且不依赖代理重复加载。
- **US2（自动化管道下载）**：作为 CLI / Agent 自动化用户，我希望在命令行查看或批量导出推文时可通过 `--download-videos` 参数一并将视频落盘并在 JSON 输出中拿到本地路径，以便接入后续剪辑、转录或知识库流程。
- **US3（高信噪比定向拉取）**：作为深度阅读者，我希望在设置中自由选择批量拉取时包含哪些内容类型（专栏文章 / 长推文 / 普通短推文），并且默认只拉取 X Article 专栏文章，从而让本地情报库保持极高信噪比。

---

## 3. 功能需求与验收标准 (F & AC)

### F1：全形态推文视频解析与文章内嵌视频还原
覆盖短推、长推（Note Tweet）与 X Article 专栏（含内嵌推文卡片）中的所有视频媒体提取与展示。

- **AC1.1（多视频提取与渲染）**：短推、长推及转推/引用推文中的单个或多个视频（`video` / `animated_gif`）均提取各自最高码率 MP4 直链与对应封面图；前端 `extractMedia()` 返回完整 `videos` 列表（同时保留 `videoUrl` / `posterUrl` 向下兼容），推文详情页渲染全部视频播放器而非仅首个。
- **AC1.2（X Article 内嵌推文与原生视频解析）**：
  - `formatArticleContent` 渲染 `TWEET` 实体卡片时，若嵌入推文包含视频（一个或多个），需在卡片对应位置输出结构化视频标记（含 MP4 直链及可选封面图），并将这些视频与封面聚合收录至主文章的 `media_urls`；
  - 同步防御性解析 `articleResult.media_entities` 中的原生视频实体（若存在 `video_info.variants` / `variants`）。
- **AC1.3（文章正文内联视频播放器）**：`TweetMarkdown` 渲染器识别文章正文及嵌入推文卡片中的视频标记，就地渲染具备完整播放与下载能力的 `TweetVideoPlayer` 组件。
- **AC1.4（真实样本完整捕获）**：对真实样本 `https://x.com/AdrianPunk115/status/2124098048842473619` 执行抓取，`fetchTweetThread` 能完整捕获全部 5 条内嵌视频推文，解析后的文章正文包含全部 5 个视频节点且均可独立播放与下载。

### F2：纯 Node.js 流式视频下载引擎与 Page Bundle 本地化存储
保持纯单运行时红线（严禁引入 yt-dlp / ffmpeg / Python 等外挂进程），通过 `undici` 流式落盘。

- **AC2.1（流式下载与防损坏）**：主进程提供视频下载服务，自动挂载 `Config.HTTP_PROXY` 并注入 `Referer: https://x.com/` 与 `Origin: https://x.com`；采用流式边下边写至 `.part` 临时文件（内存占用恒定，不整包读入 Buffer），全部写入完成后原子重命名为 `.mp4`；支持中途取消（`AbortSignal`）并自动清理 `.part` 文件。
- **AC2.2（Page Bundle 自包含存储与幂等）**：视频统一保存至 `articles/{author}/{tweet_id}/videos/<序号>_<安全名称>.mp4`；目标文件已存在且字节数 > 0 时幂等跳过网络下载并直接返回本地路径。
- **AC2.3（`index.md` 同步与级联删除一致）**：
  - 下载完成后自动同步更新该推文的 `index.md`，将对应视频记录关联到本地相对路径 `videos/<filename>.mp4`（同时保留原线上链接）；
  - 执行 `deleteTweets` 级联删除推文时，随 `articles/{author}/{tweet_id}/` 目录一并清除 `videos/` 下全部视频文件，不残留孤儿文件。
- **AC2.4（失败自愈与清晰报错）**：遇到网络超时、代理不通、HTTP 非 2xx 或写入异常时，立即清理残留 `.part` 文件，向调用方返回包含明确原因与修复建议的中文错误，不静默吞错。

### F3：GUI 视频下载交互、本地离线优先播放与自动下载配置
在桌面工作台中提供无打断、带实时反馈的下载体验与离线播放能力。

- **AC3.1（安全本地视频协议与 Range 拖动）**：Electron 主进程注册受控自定义协议（如 `xtract-media://`），严格校验请求路径必须位于当前 `Config.ARTICLES_DIR` 内（防范路径穿越），完整支持 HTTP `Range` / `206 Partial Content` 响应，确保 `<video>` 离线播放可自由拖动进度条。
- **AC3.2（播放器三态下载控制）**：`TweetVideoPlayer` 底部工具栏新增视频下载交互，覆盖三态：
  - **未下载态**：显示「下载视频」按钮；
  - **下载中态**：通过 IPC 流式事件实时更新百分比与已下载大小（如 `下载中 42% · 12.4 MB`），并提供「取消」按钮；
  - **已下载态**：显示「已下载 · 访达定位」按钮（点击调用系统文件管理器高亮选中该 `.mp4` 文件）与「本地离线」状态微标，播放器自动切换为本地视频源播放，不再走代理流式加载。
- **AC3.3（本地状态自动探测）**：切换选中推文或打开含视频文章时，自动查询各视频在 Page Bundle 中的本地落盘状态，已下载的视频直接呈现「已下载」状态并默认使用本地文件播放。
- **AC3.4（可选自动下载开关）**：设置抽屉新增「导出归档时自动下载视频」开关（持久化配置键 `AUTO_DOWNLOAD_VIDEOS`，默认关闭 `false`），开启后导出单推 Page Bundle 时自动顺带下载视频。

### F4：CLI 视频本地下载支持
保持 GUI 与 CLI 双模能力对齐，支持终端与下游 Agent 自动化调用。

- **AC4.1（命令参数与优先级）**：`--view <tweetId|url>` 与 `--export-ids <tweetIds...>` 新增 `--download-videos` 与 `--no-download-videos` 选项；生效优先级为：CLI 显式参数 > `AUTO_DOWNLOAD_VIDEOS` 配置 > 默认 `false`。
- **AC4.2（输出契约）**：启用下载视频时，stderr 打印每条视频的下载进度与结果，视频落盘至对应 Page Bundle `videos/` 并更新 `index.md`；携带 `--json` 时，stdout JSON 返回 `downloadedVideos` 字段（字符串数组，含本地绝对路径）。

### F5：拉取推文内容类型细粒度可配置（默认仅拉取 X Article）
将旧二元开关升级为三类内容多选配置，默认聚焦 X Article 专栏文章。

- **AC5.1（统一分类模型与默认配置）**：
  - 定义互斥内容类型枚举 `TweetContentType = 'article' | 'note' | 'short'`，分类纯函数 `classifyTweetContentType(tweet)` 按 `article > note > short` 判定，过滤函数 `matchesContentTypes(tweet, types)` 做集合匹配；
  - 持久化配置键为 `FETCH_CONTENT_TYPES`（逗号分隔），未配置时默认值为 `article`（仅拉取 X Article 专栏文章）。
- **AC5.2（设置抽屉多选交互与防呆）**：
  - 设置抽屉「抓取过滤规则」区域以 3 个多选标签（**专栏文章 (X Article)**、**长推文 (Note Tweet)**、**普通短推文**）替代原「仅抓取长推文与专栏文章」二元开关；
  - 默认仅选中「专栏文章」；尝试取消最后一个已选项时阻止取消并提示「至少保留一种拉取类型」；
  - 解释性说明遵循界面克制原则，统一收敛至标题/标签旁的 `InfoTip`（`i` 图标）浮层，不常驻撑高卡片。
- **AC5.3（四维批量抓取全链路生效）**：
  - 关注流（Following）、博主追踪（User）、X 列表（List）、全网关键词搜索（Search）四维批量抓取均透传并执行 `contentTypes` 过滤，贯穿 `XClient` 滚动早停计数与 `Pipeline` 入库过滤；
  - 仅勾选 `article` 时若时间线专栏密度偏低，在达到最大滚动上限或无新增批次时正常收敛返回，绝不死等。
- **AC5.4（精准单推与趋势研报豁免契约）**：
  - 单推精准抓取（`--view <id|url>`、搜索框粘贴推文链接/ID、详情页「同步全文」）不受 `FETCH_CONTENT_TYPES` 过滤限制；
  - 趋势研报（`runTrendsDigest`）内部挖掘热点讨论默认放开内容类型限制（`['article', 'note', 'short']`），确保热点实时讨论素材不被默认「仅文章」配置误杀。
- **AC5.5（CLI 覆盖与旧参数兼容）**：
  - CLI 新增 `--content-types <types>`（如 `--content-types article,note`）按次覆盖配置，非法类型值立即报错并提示合法枚举；
  - 保留旧选项 `--all-tweets` 作为 `--content-types article,note,short` 的快捷别名。

## 5. 非目标 (Out of Scope)

为防止范围蔓延，以下能力明确不纳入 `v0.1.3`：
- **不引入外部视频工具**：不集成 `yt-dlp`、`ffmpeg` 或 HLS `.m3u8` 分片转码合流（X 公开推文均提供原生 MP4 variant，直接流式下载最高码率 MP4）；
- **不做自定义「另存为」路径选择弹窗**：所有视频统一沉淀至 Page Bundle `videos/` 目录，通过「访达定位」满足拷贝/分享需求；
- **不做视频转文字 / 语音识别 / AI 视频内容总结**：留待后续版本规划；
- **不做历史存量推文的一键全库批量补下视频**：避免一次性拉爆代理流量与磁盘空间。
