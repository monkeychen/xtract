## 1. 版本策略

项目采用 **0.x 语义化版本**。当前仍处于个人工具向产品化演进的早期阶段，`0.x` 表示：

- **接口与行为尚未稳定**，仍可能因真实使用反馈调整；
- **不对外部集成提供兼容承诺**；
- 首个稳定公开契约将在 `1.0.0` 确立。

每个版本对应一份 PRD，描述该版本**已交付的完整产品状态**或**规划中的能力边界**。

## 5. 维护约定

- 版本的**已交付规格**在 `vX.Y.Z.md` 中按产品领域组织，不按迭代阶段拼接；
- 功能被砍掉时，**必须**在对应版本的「重大设计决策与功能剥离记录」中写明取消原因与对用户的影响，严禁静默移除；
- 规划中的能力一律写进下一个版本的路线图文档，不混入已交付版本；
- 版本号变更需同步更新 `package.json` 的 `version` 字段。
